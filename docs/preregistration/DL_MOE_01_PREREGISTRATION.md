# DL-MoE-01 preregistration v1.0

## Research question

Does the symmetric hierarchical DL-MoE architecture amplify the effect of
early temporal training order on mature expert-level causal specialization
relative to a contemporary eight-expert FlatMoE control, while final behavior
remains practically equivalent?

`dci_pilot` is an immutable historical baseline. Its results are not pooled
with DL-MoE-01.

## Design and frozen protocol

The factors are architecture (`FlatMoE`, `DLMoE`) and developmental history
(`INT`, `AB`, `BA`). Each of 30 primary seed blocks contains six linked models.
Ten reserve blocks are generated but cannot replace primary blocks because of
unfavorable outcomes. The planned dataset is 180 models.

Within each architecture and seed block, INT/AB/BA share an identical initial
state. Each block uses the same developmental batch identities and the same
byte-identical common phase manifest across conditions. The developmental
phase has 4,000 steps (2,000 A and 2,000 B batches); the common phase has
16,000 balanced steps.

DL-MoE has two populations, four experts per population, model dimension 128,
expert hidden dimension 256, soft routing, a 16-dimensional communication
bottleneck, learned communication gates, a shared encoder, residual population
integration, AdamW, learning rate `0.0003`, weight decay `0.0001`, batch size
`256`, 20,000 steps, no scheduler, no gradient clipping, and float32. FlatMoE
has eight experts, soft routing, and the same encoder/optimizer/training
values. The 18-dimensional input includes the optional DCI task indicator; no
router receives a separate task label.

The parameter comparability gate is `R_params <= 0.05`.

## Endpoints and hypotheses

For task T and expert e, `delta[e,T]` is balanced accuracy under normal
evaluation minus balanced accuracy after renormalized expert knockout. The
primary specialization metric is:

```text
s_expert_causal = mean_e(abs(delta[e,A] - delta[e,B]))
```

At step 20,000:

```text
A_s = ((S_DL_AB + S_DL_BA) / 2 - S_DL_INT)
      - ((S_Flat_AB + S_Flat_BA) / 2 - S_Flat_INT)
```

H2, `E[A_s] > 0`, is the sole primary scientific hypothesis. H1 (`E[D_DL] >
0`), population specialization, unrenormalized robustness, organization
distance, communication knockouts, routing, and trajectories are secondary.

Behavioral equivalence is a co-required interpretation gate. For each of eight
architecture × task × blocked-vs-INT comparisons, the 90% paired CI must lie
inside `[-0.02, +0.02]`; each architecture × condition × task must also have
mean balanced accuracy at least `0.95`. Failures are retained, not excluded.

## Statistics and exclusions

The primary analysis is a one-sample one-sided t-test on 30 seed-level `A_s`
values, alpha `0.05`. Report mean, median, SD, SE, Cohen's dz, sign counts,
and a 10,000-sample seed-block percentile bootstrap CI. A deterministic
100,000-draw sign-flip test is a robustness analysis. H1/H4/H5 report raw and
Holm-adjusted p-values. No outlier or outcome-based exclusions are allowed.

Strong support requires positive mean A, primary p < .05, bootstrap lower CI
bound > 0, and the full behavioral-equivalence gate. If H2 is unsupported, the
architecture-amplification claim is unsupported; if H3 fails, no
comparable-behavior claim is allowed.

## Reproducibility and freeze

`seed_manifest.csv` is generated by the hash rule in `protocol.py` using root
`DL-MOE-01-CONFIRMATORY-v1`. Raw checkpoints and intervention profiles are
separate from required long-format CSV tables. Protocol hashes, config hash,
code commit, environment, and incidents are recorded before training.

This document is a preregistration candidate until validation passes and a tag
is created. Any later protocol change requires a versioned deviations document.
The full 180-model confirmatory series is intentionally not run by this
preregistration preparation task.
